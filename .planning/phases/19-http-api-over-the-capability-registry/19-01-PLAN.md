## Named decisions recorded by this plan

- **D-09 — the install root is launch context, not an `invoke()` argument.** `registry.invoke`'s
  signature stays `(self, cap_id, payload)`; `tests/integration/test_surface_parity.py::test_seam_has_no_leniency_knob`
  asserts exactly that set and the seam docstring forbids per-surface knobs. The install root is
  therefore process-level launch state in `capabilities/workspaces.py`
  (`set_launch_install_root` / `launch_install_root`), defaulting to `Path.cwd()` resolved at call
  time (the WR-09 idiom `cli.py:1034` already uses). Every surface resolves against the same value,
  so this adds uniform behaviour, not a knob. — *Reversibility: costly* (all three surfaces read it).
- **D-10 — the HTTP envelope refuses path-shaped payload keys server-side.** Under D-05's single
  envelope the payload comes from the client verbatim, so "the adapter can only ever emit
  `workspace_id`" cannot be a client-side property. The route rejects any key in `PATH_SHAPED_KEYS`
  (derived from the field map, never hand-listed) with 422 before dispatch. This is HTTP's trust
  boundary refusing caller-supplied filesystem paths — HTTP-03's literal wording — and is not the
  rejected "adapter-side resolution" alternative: *resolution* still happens only in the seam.
- **D-17 — token delivery is stdout plus a `0600` file, and static serving is not pulled forward.**
  `construct serve` prints the token and writes `{install_root}/.construct/api-token` with mode
  `0600`, so Phase 21 has a file to read without a protocol change. Injecting the token into a
  server-rendered `index.html` would pull Phase 21's static serving forward and is declined.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/`curl` -> ASGI app | Untrusted HTTP request enters the process; everything before `LocalhostGuard` returns is attacker-controlled |
| HTTP payload -> `registry.invoke` | Caller-supplied JSON becomes capability input; the install root is the authorization boundary |
| launch process -> filesystem | The token file and the install-root scan are process-level state a request must never redirect |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-01 | Spoofing / EoP | `LocalhostGuard` Host check | high | mitigate | DNS-rebinding defence: `Host` (port stripped) must be in `ALLOWED_HOSTS`, else 400 before dispatch |
| T-19-12 | Info disclosure / EoP | `LocalhostGuard` Origin check | high | mitigate | `Origin` present and not allowlisted returns 403 per the MCP specification; absent is allowed so non-browser clients work |
