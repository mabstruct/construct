<objective>
Turn OQ-4 from an accident into a contract.

RESEARCH measured that the premise recorded in CONTEXT.md is false: `SqliteSaver.setup()` already
executes `PRAGMA journal_mode=WAL` as the first statement of its `executescript`, WAL persists in
the database header so a fresh connection to the same file also reports `wal`, and Python's
`sqlite3.connect()` already defaults to `timeout=5.0` i.e. `busy_timeout=5000`. The preferred
"WAL + `busy_timeout`, no locking" contract is therefore already in force — by library default and
stdlib default, not by decision. That is the worst state a contract can be in: correct today,
silently reversible by a dependency bump, with no test that would notice.

Purpose: HTTP-06 makes a browser-spawned run and a CLI resume write the same checkpoint file. The
concurrency contract stops being theoretical the moment that is possible, and this repo's named
default failure mode is exactly the silent kind.
Output: both checkpointers declare their own PRAGMAs, a test pins them, and ADR-0004 records the
limitation that is real — `SqliteSaver`'s `threading.Lock` is per-instance and gives no
cross-process guarantee at all.
</objective>

## Named decisions recorded by this plan

- **D-14 — the checkpoint concurrency contract is WAL plus an explicit 30 000 ms `busy_timeout`,
  with no locking.** Concurrent readers never block; a writer waits rather than erroring. Two
  racing resumes are already arbitrated correctly by the Phase 18 D-11 checkpoint-id ETag — the
  loser rejects with zero writes, which is the right outcome. A server-held single-flight lock was
  rejected because the guarantee would be one-sided (a CLI resume cannot see it), and a lockfile
  was rejected because stale-lock recovery's failure mode is a permanently un-resumable run.
  30 000 ms rather than the inherited 5 000 ms because a curation resume that writes many cards
  holds the write lock for an unbounded interval, and a too-short timeout surfaces as
  `database is locked` mid-resume — the exact failure OQ-4 exists to prevent. —
  *Reversibility: reversible* (two constants and a docstring).

Second, the limitation, stated rather than implied away: `SqliteSaver.__init__` holds a

cross-process mutual exclusion and none is being added.

server-held single-flight lock was not chosen (its guarantee would be invisible to a CLI resume).

permanently un-resumable run.
