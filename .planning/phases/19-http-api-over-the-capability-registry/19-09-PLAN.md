<objective>
Make a workflow run an addressable resource that outlives the process that started it.

The locked constraint is that a synchronous call is not an option: criterion 5 requires the id to
return immediately and the run to be pollable *while still running*. A detached subprocess makes
that cheap here, because almost everything already exists — the run id can be minted before the
process starts and both run inputs already accept one; the inspect capabilities already reconstruct
status from the persisted checkpoint without resuming, surfacing an awaiting-review run with its
pending queue; and cross-surface resume falls out for free because both sides are just processes
writing the same checkpoint file.

Purpose: this is the requirement that turns HTTP from a request-response veneer into something the
browser can actually run work through, and it is where the project's named failure mode bites
hardest — a spawn that fails into a pipe nobody reads shows up as a run that never existed.

Output: a run-start route behind the same guard as the envelope, error output captured to a file
the browser can ask for, and cross-surface resume proven in both directions.
</objective>

## Named decisions recorded by this plan

- **D-12 — a run is started by a detached subprocess, and only *starting* is a non-capability
  route.** Crash isolation, no cross-thread database question, and browser/CLI symmetry all fall
  out for free, because both sides become processes writing the same checkpoint. An in-process
  worker thread was rejected because a server restart silently kills a run; a bounded pool was
  rejected because a queued-but-not-started run is a status the checkpoint knows nothing about.
  Polling and resume stay on the ordinary capability envelope, so the non-capability surface is
  exactly one route wide. — *Reversibility: costly* — the browser, the CLI and the checkpoint all
  observe the process model, and changing it changes what a run's absence means.
- **D-15 — progress is polled, not streamed.** Server-sent events are deferred to Phase 21, which
  owns the guided layer and can judge whether node-boundary progress actually hurts. Polling costs
  nothing new, works identically for a run this server did not start, and degrades to reloading the
  page; streaming is real new server surface — long-lived connections and reconnection — inside the
  phase everything downstream already depends on.
- **D-26 — the run's error output goes to a file under the workspace's durable-state tree and is
  named on the status response.** A pipe nobody reads is the project's named silent-failure mode
  wearing a new costume: a bad credential, an import error or a wrong working directory would make
  the run appear as "no such run" forever.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request -> process spawn | Caller input reaches an argument vector for a new operating-system process |
| spawned child -> workspace | The child writes canonical state and durable checkpoints under the resolved workspace |
| child error output -> caller | The log file is environment-revealing text produced outside the sanitizer's reach |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-09 | Elevation of privilege | the run spawner | high | mitigate | Spawn with an argument list, never a shell; the run id is kebab-validated before it reaches the argument vector; the workflow name is checked against the registry-derived startable set |
| T-19-25 | Elevation of privilege | remote-code-execution capabilities reaching HTTP | high | mitigate | The tool-path spike command is not in the registry at all and is therefore unreachable by construction, not by an opt-out; the startable set is derived from registry run capabilities only |
| T-19-03 | Tampering / Info disclosure | workspace resolution for a run | high | mitigate | The run route resolves `workspace_id` through the same seam helper as the envelope and refuses path-shaped keys identically |
| T-19-05 | Information disclosure | the run's error-output file | medium | mitigate | The response names the file's relative path; raw child error text is not echoed into a response body |
| T-19-26 | Tampering | a resume silently swallowed | high | mitigate | Resume goes through the review capabilities, which wrap the payload; the tests assert persisted state after a resume, so a swallowed resume fails rather than returning a well-formed response |
| T-19-10 | Denial of service | unbounded run spawning | low | accept | Single-user local proof of concept; recorded in `src/construct/api/COVERAGE.md` rather than left silent |
| T-19-13 | Tampering | two processes resuming one run | medium | mitigate | The concurrency contract from plan 19-02: WAL plus an explicit busy timeout, with racing resumes arbitrated by the checkpoint handle so the loser writes nothing |
</threat_model>
