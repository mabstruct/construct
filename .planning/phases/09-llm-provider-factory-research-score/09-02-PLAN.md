def clamp_action(llm_action, score, relevance, card_create):
    if score < relevance:    return "skip"
    if score < card_create:  return "ref_only" if llm_action != "skip" else "skip"

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SearchResult snippet/url -> LLM prompt | Untrusted fetched web content crosses into the scoring prompt and could attempt to steer the ingest_action (prompt injection). |
| LLM structured output -> finding contract | The model proposes ingest_action and source_tier; this output is untrusted and must be validated + clamped. |
| gate -> workspace | The gate reads taxonomy/governance and MUST NOT write to the workspace SOT. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Elevation of Privilege | score_one / clamp_action | mitigate | Python ceiling-clamp (D-05) enforces governance deterministically; the LLM can only be more conservative, never more permissive. Unit tests assert clamp-down at both bands. |
| T-09-02 | Tampering | score_one prompt (SearchResult snippet/url) | mitigate | Output constrained to the ScoredFinding schema via `with_structured_output`; no tool execution; the deterministic clamp governs the final action; no workspace write; human review (Phase 10) precedes any SOT change. |
| T-09-05 | Spoofing/Info-Disclosure (Access Control V4) | governance/taxonomy loaders | mitigate | Loaders use read-only `WorkspaceLoader`; grep gate asserts no write/open/mkdir in research_score.py. Hard no-writes boundary. |
</threat_model>
