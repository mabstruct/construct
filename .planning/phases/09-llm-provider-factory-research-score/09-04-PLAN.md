<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/stdin payload -> handler | The pre-fetched SearchResults JSON is untrusted input; Pydantic (`SearchResult` extra="forbid", `ResearchScoreInput` extra="forbid") validates it at the boundary. |
| gate outage -> CLI/MCP result | A provider outage must surface as a failed result, not a misleading success. |
| handler error -> user output | Error messages reaching the CLI/MCP must not leak provider API keys. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-V5 | Tampering (Input Validation) | research_score_cmd / _research_score_shim | mitigate | Untrusted payload validated by `SearchResult`/`ResearchScoreInput` (`extra="forbid"`, range-checked fields) before scoring; malformed input is rejected at the boundary. |
| T-09-03 | Information Disclosure | _research_score_shim error mapping | mitigate | Outage/error -> sanitized OperationResult message (no raw provider exception / API key); reuse the Plan 03 sanitized cause. |
| T-09-04 | Repudiation / Availability | _research_score_shim success mapping | mitigate | Total outage (D-09) maps to `OperationResult(success=False)`; the contract test asserts a zero-usable-findings outage is NOT reported as success. |
</threat_model>
