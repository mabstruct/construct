<objective>
Convert every remaining in-repo caller onto the seam, retire the dual-mode shims the old
positional calling convention required, and register `views validate` as a capability so the
last hand-written command group joins the registry.

Purpose: Plan 01 proved the seam on one capability. GOV-01 is only satisfied when there is no
second path. Research measured 25 handler call sites in `cli.py` — not the three CONTEXT.md
names — plus three non-CLI, non-MCP in-repo callers, one of which is a capability calling
another capability positionally. Every one of those is a way for a payload to reach a handler
without passing the `input_model`.

Output: one dispatch path in the repository, a catalog free of positional-passthrough branches,
`views validate` as `views.validate_data`, and a parity table broad enough that Phase 19's HTTP
surface joins by adding a column rather than by forking the suite.
</objective>

passing a default. Document which capabilities took which treatment in the SUMMARY. This
repository has already lost user prose twice to exactly this class of defect (the `archive_card`
body destruction closed by commit `4e2b909`, whose damage is unrecoverable), so treat a blanked
field as a data-loss bug, not a cosmetic regression.

Second, do not change any command's exit-code behaviour. The Phase 11 curation exit-code contract
holds (D-15): a degraded run still exits 0. Conversion is about the dispatch path, not the
process contract.

Leave the `views` command group alone in this task — Task 3 owns it. Leave `spike` and `tag`
alone entirely.

## Prohibition recall (spec-less fallback, §B)

Stage 1 over-produced ten must-NOT candidates for GOV-01; Stage 2 kept one, which is authored
descriptor-less into `must_haves.prohibitions` above: the seam must not blank a field the caller
never mentioned. It is bespoke to this product (this repository has destroyed user prose twice
through exactly this class of defect and the damage was unrecoverable), it is not covered by any
canon tool, and it survives the routine-engineering filter because the harm is user data loss,
not a correctness nit.

Canon-referral breadcrumbs — surfaced, deliberately not minted as prohibitions:

- Path traversal via an agent-supplied `install_root` or capability payload is canon — covered by
  `/gsd-secure-phase` and by the existing `install_root_error` marker guard; recorded as threat
  T-18-07 in the register below rather than as a prohibition.
- Error-message information disclosure (a rejection echoing a filesystem path) is canon — covered
  by `/gsd-secure-phase`; recorded as T-18-10 and as an acceptance criterion on Task 3.
