<objective>
Delete the surface that writes canonical truth without a gate behind it, and replace it with a
guard that fails the moment a second one appears.

Purpose: `ui/gate_review.py` builds its review queue entirely from Streamlit session state with no
run behind it, flips a review status while writing a real approval into the same append-only audit
trail the curation graph writes to — approvals recorded for things nothing applied — and calls a
connection-writing capability directly with a hard-coded connection type, ignoring whatever the
connection-typing gate decided. It is a second canonical writer with different semantics from the
apply node, reachable without any paused checkpoint to resume into. This is an access-control
defect wearing a UI costume.

Output: the file and its navigation entry gone, and a source-level invariant test that makes the
removal permanent instead of merely current.
</objective>

**D-14 — the ROADMAP criterion this plan satisfies has been restated.** Success criterion 4 was
written as "Approving a proposal in the Streamlit gate-review screen produces exactly the same
canonical writes and event records as approving it through the reviewed workflow's own resume

ROADMAP.md as two independent halves: **no surface writes canonical truth outside the reviewed
workflow's resume path** — satisfied by removal, guarded by this plan's test — **and no approval
event exists for a decision that was never applied**, which stands on its own and is enforced by
Plan 08's conditional-emission work.

**Keep the event strings.** Every repository match for the removed module's name that is not the
module itself is either the research graph's LangGraph node of the same name (unrelated, keep) or
the approval and rejection event action strings (keep — Plan 08 owns their emission conditions).
Deleting a string because it shares a name with a deleted file would break the audit trail this
phase is trying to make honest.

<assumption_delta_decision>
**Signal:** the phase scope text — *"leaving a second UI that forges gates is worse than either
keeping or deleting it"* — pluralizes a noun that had been singular. A core assumption lost its
monopoly.

**The noun that is now primary:** **canonical writer**. What used to be an implicit singleton
("the apply nodes write canonical truth") is now an explicitly plural category with a stated
cardinality of one. The generalized identity is *"a canonical writer"*, and the system's claim is
that exactly one exists.

**Decision: `promote`.** The generalized noun is promoted to primary, and the invariant is
written as a property of the category rather than as a property of one module. Concretely: Task 2
does not test "gate_review.py does not write"; it tests "no module outside the apply nodes
reaches a canonical write function", enumerated by walking the source tree. D-13 already resolved
the substance by deleting the offending module; this records that the *shape* of the invariant
changed with it.

**Rationale:** an invariant phrased against one named module goes green the moment that module is
deleted and stays green while a third writer is added elsewhere. Phrasing it against the category
is what makes it a contract instead of a snapshot.

**Companion invariant:** the guard in Task 2 goes red the instant a future phase reintroduces a
second canonical writer. That is GOV-04's source-level guard, so the two are wired together rather
than duplicated — there is one test, not a deletion test plus a category test.
</assumption_delta_decision>
