<objective>
Stop three surfaces from reporting outcomes that did not happen: make escalation honest about
writing nothing (D-16), make the approval event conditional on an actual write (D-16's event-count
invariant, which is the second half of the restated criterion 4 under D-14), and make a degraded
run read as degraded everywhere it is reported (GOV-05), while preserving exit codes (D-15).

Purpose: the result model is honest and the per-step status line is honest, and then the terminal
verdict glyph contradicts both in the same output block. Escalation is worse — it reaches no CLI
renderer at all, and it is currently logged as a *rejection*, so the audit trail records a
decision that was never made about an item nothing happened to. And the approval event fires on
all three branches of every apply node: on a real write, on an idempotent no-op, and on a write
that failed. Each of these is the same defect class this codebase already names, and this plan
closes the phase by removing them.

Output: an escalate outcome with its own event action and its own bucket, approval events that
only follow writes, honest rendering on all three surfaces, and a regression guard pinning the
exit-code contract that this work must not disturb.
</objective>

**D-15 is a hard constraint on this plan, not a goal of it.** The Phase 11 curation exit-code
contract holds: a degraded run still exits 0 on purpose. GOV-05 governs what a surface *reports* —
status fields, JSON payloads, MCP results, human-readable output — not process exit semantics,
which the CLI uses to mean "the command ran". Re-opening that decision sideways inside a repair
phase is exactly what recording it was meant to prevent. Every mechanism chosen here must leave
exit codes untouched, and Task 3 pins that with a regression test.

**Out of scope by decision.** Giving escalation a real write path — actually routing an escalated
item somewhere for follow-up — is new capability, not a Phase 18 repair. This plan makes escalation
honest about writing nothing; it does not make it write something.

**Where the defect is not.** `escalate` is not a rendering bug to be renamed: it reaches no CLI
renderer at all. The state channel exists and the apply node returns it; the gap is between the
result payload and the renderer. Treat this as *adding* a surface field, not renaming one.
</context>
