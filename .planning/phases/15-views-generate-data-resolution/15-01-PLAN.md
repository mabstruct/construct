<objective>
Vendor the 15-module views library out of the deployed skill directory and into the shipped
`construct` package, delete the interpreter-search-path injection that made `construct.views.generate`
importable only inside a dev checkout, and declare the YAML dependency the vendored code needs.

Purpose: implements D-08 and resolves the second half of ROADMAP criterion 3 (the
deployed-skill-directory import coupling). Today `_PROJECT_ROOT = Path(__file__).resolve().parents[3]`
resolves to the repo root and `pyproject.toml:38` ships only `src/construct` — so an installed
CONSTRUCT raises `ImportError` at module load, before any handler runs. Every other plan in this
phase depends on the generator being importable from an installed package.

Output: `src/construct/views/lib/` (15 modules + `__init__.py`), a clean import block in
`generate.py`, `pyyaml>=6` in `pyproject.toml`, and a unit test that fails if the coupling returns.
</objective>
