<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted search result (URL/title) → ref-ID / filesystem | Provider-supplied URL and title flow into ID derivation and ledger keys. |
| rejected ledger file → dedup decision | The ledger gates whether a previously rejected finding can be re-proposed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03 | Tampering | `ref_id_for` from malicious URL/title | mitigate | ID is kebab-slug(title, regex-stripped) + sha1(normalized_url) hash — raw URL path never reaches the filename, so no path traversal; output asserted against KEBAB_CASE_PATTERN. |
| T-10-04 | Tampering (integrity) | rejected ledger silent re-ingest | mitigate | `rejected_normalized_urls` feeds the dedup filter so a rejected URL cannot be re-proposed on rerun (RSCH-05); ledger lives outside SOT so a corrupt ledger cannot forge a ref. |
| T-10-05 | Denial of Service | malformed/missing ledger file | mitigate | `load_rejected_ledger` returns an empty ledger on missing file and must not crash the dedup node. |
</threat_model>
