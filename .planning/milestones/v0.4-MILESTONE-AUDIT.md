# Milestone Audit: CONSTRUCT v0.4 Agent Workflows

**Audited:** 2026-07-19 (retrospective) · **Status:** ⚠️ gaps_found (runtime sound, surfaces broken)
**Milestone shipped:** 2026-07-07 · **Closes the audit gap** named in `RETROSPECTIVE.md`.

## Summary

v0.4 delivered 22/22 requirements across 6 phases (8–13) with 404 tests green. The audit
confirms the runtime is real and well-built. It is **not** a case of overstated delivery.

What the milestone did not do is reconnect the delivered runtime to the surfaces users and
agents actually touch. Every documentation file outside `.planning/` was last committed
**2026-06-21 — the day v0.4 started**. Four doc files changed during the entire execution,
each forced by an individual phase requirement. As a result the flagship capability of the
milestone (`daily.run`) has no Claude-native entry point, and four skills invoke CLI
commands that do not exist.

The distinction matters for planning: **this is not a quality problem in v0.4's engineering.
It is a missing integration step.** The fixes are small and bounded, which is precisely why
they suit a v0.4.1 patch rather than being folded into v0.5.

## Live Defects

### V41-01 — `views.generate_data` is a permanent-failure stub on the MCP surface

`catalog.py:317`:

```python
handler=lambda **kwargs: OperationResult(success=False, message="Not yet implemented — see Plan 02")
```

This capability is advertised on the MCP surface (`construct_views_generate_data`) and always
fails. Meanwhile a **real, complete** `generate()` implementation sits unused at
`views/generate.py:175`.

**This is not a trivial wiring fix.** Two genuine obstacles:

1. **Signature mismatch** — `generate(install_root: Path)` vs `ViewsGenerateDataInput.workspace: Path`
   (`catalog.py:149-150`). These are different concepts, not a rename.
2. **Deployment coupling** — `generate.py:43-51` imports its pipeline from the *deployed skill
   directory* (`construct-views-generate-data/`), so the runtime depends on installed Claude
   config layout. That coupling needs a decision before wiring.

**Blast radius:** four documented callers route here — `construct-curation-cycle/SKILL.md:122,128`,
`construct-research-cycle/SKILL.md:109,113`, and `construct/workflows/daily-cycle.md:106`. The
daily-cycle skill owns "the single post-run views refresh" per Phase 13 D-10, so the final step
of the freshly-shipped daily cycle is non-functional. It degrades gracefully, but its remediation
message tells the user to run the same non-existent command manually.

**Provenance:** logged in `v0.3-MILESTONE-AUDIT.md` tech_debt (phase 04) and carried through all
of v0.4 untouched. It has now survived two milestones.

**Also note:** this stub directly contradicts invariant I1 in `architecture-overview.md:99`
("Only `views-generate-data` writes to `views/build/data/`").

### V41-02 — Streamlit ops UI points at a config file the runtime never reads

`ui/streamlit_app.py:24` defaults the "LLM config path" field to `.construct/model-routing.yaml`.
`llm/config.py:49` reads `src/construct/llm/config.yaml` (env override `CONSTRUCT_LLM_CONFIG`).

`.construct/model-routing.yaml` is still copied into every new workspace by `services/init.py:58`
but is read by nothing. It is vestigial, and three docs still describe it as authoritative
(`workspace-contract.md` Support table, `config-topology.md:56,135`).

**Decide and record:** either re-point the UI and mark `model-routing.yaml` deprecated, or
delete it from init. Leaving it copied-but-unread guarantees recurring confusion.

## Architectural Finding — durable state contradicts stated invariants

The LangGraph SQLite checkpointers at `.construct/workflow/*.sqlite` hold **pending human-review
decisions that are not reconstructible from layer 1**. This is durable state that partly owns
truth.

Two architecture documents say this should not exist:

- `architecture-overview.md:243` — "Add a database that owns part of the truth → reconsider."
- `nfrs.md` §2 — "No SQLite index to rebuild… no derived state that's required."

**The implementation is correct; the documented invariant is stale.** But nobody wrote down that
it changed, and `workspace-contract.md` does not list these files among workspace artifacts at all.

**This must be settled before v0.5.** A UI-primary shell will need to reason about resumable gate
state across sessions and processes. Resolving it after the UI is built means resolving it twice.

## Root Cause

Phase verifications passed because they tested the Python layer directly. **Nothing tested that
a documented command string resolves against the registry.** The `test_mcp_no_hardcoded_*`
invariant already works well for MCP parity; the same technique applied to `construct ...`
strings in SKILL.md and workflow docs would have caught every V41-03 item automatically.

This mirrors the retrospective's own top cross-milestone lesson — *unit-green ≠ wired* — one
layer further out than it was previously applied.

# Proposed v0.4.1 Scope

A bounded patch milestone. Rationale: these are integration defects in shipped work, not new
capability. Folding them into v0.5 would mean building a UI on surfaces known to be broken, and
would obscure v0.5's own delivery signal.

**Suggested definition of done:** every documented invocation path resolves and executes;
the v0.4 runtime is discoverable by both users and agents; the architecture doc set describes
the system that actually exists.

### Sequencing note

DOC-03 gates v0.5 design and should land early.

FIX-04 landed first (2026-07-19) rather than last, using a shrinking allowlist instead of a
failing suite. This inverts the original sequencing for a reason: the guard now *defines* the
remaining work. FIX-01 and FIX-03 are complete precisely when `_KNOWN_BROKEN` is empty, and the
allowlist cannot be quietly widened without a reviewer seeing it.

**Independent confirmation of V41-03:** mutation-testing the guard (emptying the allowlist)
re-derives all six broken references in exactly the six files this audit names — the defect list
was reproduced by a mechanism independent of the manual review that produced it.
