# Milestone Audit: v0.4.1 — Surface Integration & Documentation Truth

**Audited:** 2026-07-26
**Status:** `gaps_found`
**Milestone shipped:** 2026-07-25 (tag `v0.4.1`)
**Suite at audit time:** 524 passed, 1 skipped, 2 warnings

This is the audit that was not run before close. It is retrospective, like the
`v0.4-MILESTONE-AUDIT.md` that scoped this milestone in the first place.

## Verdict

The milestone's stated work was genuinely done. Every requirement's own acceptance
criteria hold under independent re-verification, and the mechanical guards
(`_KNOWN_BROKEN` empty over a widened `_DOC_GLOBS`, `test_artifact_catalog.py`
introspection) are real and non-vacuous.

Two things force `gaps_found`:

1. **FIX-02 is partial** — one doc surface still contradicts the recorded decision,
   and it is the surface shipped into every user workspace.
2. **The flagship end-to-end flow does not carry data** — a card created through the
   supported CLI path is silently dropped by `views generate`. This is not a
   regression introduced by v0.4.1; it is a pre-existing writer/parser contract fork
   that only became observable *because* Phase 15 made `views.generate_data` real.
   That is the milestone working as intended and finding one more defect on its way.

Neither gap invalidates the shipped work. Both belong in v0.5's first phase.

## Deliberate Deferrals — Confirmed Still Correctly Scoped

These were checked to make sure none had silently degraded from "documented deferral"
into "broken flow". All three remain deliberate, pinned, and correctly scoped.

- **`views validate` rejects 3 of 8 generated files.** Reproduced live:
  `5 passed, 3 failed, 0 missing`, with `stats.json` failing on Pydantic
  `extra_forbidden`. Exactly what `test_views_validate_does_not_yet_accept_generated_bytes`
  documents. Still ownerless; still a v0.5 prerequisite.
- **Per-card views refresh removed with the debounce hook.**
  `adr-0005-views-refresh-ownership.md:108` names `views.per_card_hooks.*` in
  `templates/config.yaml` and `README.md:263-264` as inert and flags the doc-truth
  cleanup for a later phase. The ADR itself carries the deferral.
- **`card list` MCP boundary.** Narrowed by live testing: `OperationError` output
  serialization *does* work (`_serialize_result` handles the failure path). The real
  gap is narrower than logged — `knowledge.card.list` is registered with `list_cards`
  as a bare handler, with no input-model shim, so `CardListInput` validation never
  runs. Mistyped input is accepted silently.

## Process Observations

- **The audit-before-close lesson still has not been institutionalized.** v0.4 skipped
  its audit and v0.4.1 became the remediation. v0.4.1's own retrospective records this
  as Top Lesson #3 — and v0.4.1 then closed without an audit too. This document is the
  second retrospective audit in a row.
- **`requirements-completed` frontmatter is unreliable as an audit source.** Two
  requirements (FIX-03, UX-01) are absent from every SUMMARY; one (DOC-04) uses the
  underscore variant `requirements_completed`. 12 of 20 SUMMARYs omit the field. The
  three-source cross-reference only worked because `VERIFICATION.md` and the
  traceability table were complete.
- **Fixtures masked the writer/parser fork.** The views tests pass because their
  fixture cards (`test-ws/*/cards/*.md`) are hand-authored with `lifecycle:` present.
  No test creates a card through `create_card` and then parses it. A green suite again
  was not integration coverage — the same lesson as v0.3, in a new place.
