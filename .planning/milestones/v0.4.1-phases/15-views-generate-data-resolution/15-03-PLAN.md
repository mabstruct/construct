| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-15-08 | Tampering | `ViewsGenerateDataInput.install_root` → `generate()` writes under `<install_root>/views/build/` | medium | mitigate | An MCP-supplied path drives directory creation and file writes. Mitigated by Pydantic `Path` typing on the input model plus `discover_workspaces` iterating only real `iterdir()` entries — workspace ids are existing directory names, never caller-supplied strings, so no caller-controlled segment reaches the output path. No path normalisation beyond the existing model is added; the surface is local-first single-user. |
| T-15-09 | Repudiation | `_KNOWN_BROKEN` allowlist | high | mitigate | Widening the allowlist would silently convert a live defect into an accepted one with no audit trail. Mitigated by the paired still-broken assertion (a landed fix forces deletion) plus this plan's exact-set acceptance criterion asserting the remaining four keys by name and the single-deleted-line diff check. |
| T-15-10 | Information Disclosure | `OperationResult.message` / `--json` output | low | accept | Generation output embeds workspace and file paths in errors and warnings. Local-first, single-user, and consistent with existing `views validate` output. No remote surface. |
| T-15-11 | Spoofing | CLI and MCP reaching `generate()` by two independent code paths (D-03) | medium | accept | The two surfaces can drift — a fix applied to one may not reach the other. Accepted deliberately and recorded: RT-01/RT-02 stays open for the views group, `REQUIREMENTS.md:51`'s bounded exception is declined, and PROJECT.md's registry-coverage "Revisit" note stays accurate. Both paths are covered by tests in this plan (registry handler in Task 1, CLI command in Task 2) so drift surfaces as a test failure rather than silently. |

ASVS level 1; blocking threshold `high`. T-15-09 is mitigated with automated criteria in this plan.
