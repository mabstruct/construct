<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| approved decisions (Command resume) → SOT writes | Only approved findings may become refs/cards; rejected ones must be blocked AND remembered. |
| checkpoint DB across processes → resume | A fresh process re-opens the same DB and continues; tampered/corrupt state could replay writes. |
| rejected ledger → future dedup | A previously rejected finding must never be silently re-ingested. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-10 | Elevation of Privilege | rejected finding re-ingested | mitigate | reject path writes only to the ledger; deduplicate (Plan 03) filters incoming against the ledger so a reject is never re-proposed (RSCH-05). |
| T-10-11 | Tampering (integrity) | rerun / partial-batch double-write | mitigate | deterministic ref_id_for + skip-if-exists; checkpoint resume re-runs only unfinished writes (test_idempotent_rerun, test_partial_batch_resume_safe). |
| T-10-12 | Info Disclosure | checkpoint DB committed / leaks | mitigate | DB under `.construct/` (git-ignored in Plan 01); holds orchestration state only, not secrets. |
| T-10-13 | Tampering | malicious URL path traversal in ref filename | mitigate | ref_id_for is kebab-slug + sha1 hash (Plan 02); raw URL path never reaches the filename; ReferenceRecord.id validated kebab. |
| T-10-14 | Repudiation | missing audit trail | mitigate | append-only D-11 events (research_*_complete, gate_review_approved/rejected) via non-blocking append_event; never truncate log/events.jsonl. |
</threat_model>
