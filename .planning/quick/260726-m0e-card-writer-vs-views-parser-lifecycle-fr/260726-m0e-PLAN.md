<objective>
Close the card-writer / views-parser frontmatter fork found by the v0.4.1 milestone audit
(2026-07-26, `gaps.integration[1]` / `gaps.flows[0]`).

`schemas/card.py:103` declares `lifecycle: Lifecycle = Lifecycle.seed` — optional with a
default — so `_card_dict_to_markdown` never emits the key for a fresh card and
`validate_card_write` still passes, because Pydantic fills the default in memory.
`views/lib/parse_cards.py:7` reads *raw* frontmatter and lists `lifecycle` in
`REQUIRED_FIELDS`, so it drops the card and files an advisory warning. Result, reproduced
end to end: `construct views generate` reports `11 files written, 0 validation errors,
1 content warnings`, exits 0, and writes `{"cards": []}`.

Latent until Phase 15 — before `views.generate_data` stopped being a permanent-failure
stub, the writer/parser round trip was never exercised.

This is a RED -> GREEN pair plus a coupled data backfill: Task 1 lands a round-trip guard
that fails against today's writer, Task 2 fixes the writer until it passes, Task 3
backfills the three repo fixtures the strict parser still drops.

Purpose: make the frontmatter on disk self-describing, per adr-0001's markdown-as-truth
invariant, so no reader has to re-derive schema defaults the writer knew and did not write.
Output: one serializer default, two permanent round-trip guards, three backfilled fixtures.
