<defect_analysis>
Verified live before planning. Do NOT re-derive — reproduce it as the RED step instead.

**The defect** (`src/construct/services/knowledge.py`, current line numbers):

- `:335` — `_, _, raw = _read_card_file(root, card_id)` discards the middle return value.
  `_read_card_file` (`:138`) returns `(card, body, raw_frontmatter_dict)`.
- `:350` — `markdown = _card_dict_to_markdown(raw)` is called with `body` left at its `None`
  default. `_card_dict_to_markdown` (`:98`, `:116-117`) substitutes the canonical empty section
  template whenever `body is None`.

Net effect: the real body is replaced by empty `## Summary` / `## Evidence` / `## Significance` /
`## Open Questions` headings. Live repro: a card created with `--summary "IMPORTANT BODY TEXT"`
came back from archive with an empty Summary section.

**The correct sibling:** `edit_card` reads `_, body, raw = _read_card_file(...)` at `:265` and
serializes with `_card_dict_to_markdown(raw, body=body)` at `:285`. The body round-trip through
`parse_card_markdown` -> `_card_dict_to_markdown` is therefore already proven in production by
`edit_card`; this fix only restores the same two links in `archive_card`.

**Automatic reach (confirmed, affects test scoping):** `src/construct/llm/curation_run.py`
`apply_archives` calls `archive_card(workspace, card_id, author=CardAuthor.curator)` at `:963`
(function at `:930-972`) for every approved decay/archive proposal. No user types `archive` for
that path. `apply_archives` performs no body handling of its own — it delegates wholly to the
service function. **Scoping decision:** because both the manual CLI path and the automatic
curation path funnel through the single `archive_card` service function, one service-level
regression test covers both reaches. No new test in `tests/llm/test_curation_run.py` is required,
and none is in scope for this plan.

**Pre-existing-test survey (repo_facts item — result recorded, no correction needed):** no
existing test encodes the buggy expectation.
- `tests/unit/test_knowledge_operations.py:211-237` (`TestCardArchive`) asserts frontmatter only
  (`lifecycle`, `connects_to`); it never looks at the body.
- `tests/integration/test_knowledge_cli.py:174-190` (`test_card_archive_cli`) asserts only that
  `"archived"` appears somewhere in the file.
- No golden-file comparison of an archived card exists anywhere under `tests/`.
Therefore nothing has to be un-asserted, and no silent test correction is being made. Task 3
*strengthens* the CLI test rather than correcting it.
</defect_analysis>
