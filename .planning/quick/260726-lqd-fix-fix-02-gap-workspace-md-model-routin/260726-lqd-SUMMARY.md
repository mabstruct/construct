# Quick Task 260726-lqd: Fix FIX-02 gap — WORKSPACE.md model-routing prose

Closed the FIX-02 documentation gap found by the v0.4.1 milestone audit: `construct init`
was the fifth (and missed) writer describing `.construct/model-routing.yaml`, and the only
one still calling it a live routing source — so every new workspace shipped a
self-contradicting `WORKSPACE.md`. Corrected the generated bullet and landed a non-vacuous
contract guard that reads the generated bytes.

## What Was Built

**Task 1 (RED) — `tests/contract/test_generated_workspace_doc.py`** (commit `0d1629f`)

Two tests plus three extractors, in the house style of `tests/contract/test_artifact_catalog.py`.
A module-scoped fixture calls `initialize_workspace()` into a fresh `tmp_path_factory`
subdirectory and returns the resulting `WORKSPACE.md` text — the guard never reads the
string literal in `init.py`.

- `test_generated_workspace_doc_extraction_is_not_vacuous` — the anti-vacuity floor: title
  present, all three headings (`## Canonical Paths` / `## Derived Paths` / `## Support Paths`)
  present, at least 2 bullets in the Support Paths section, the model-routing row found and
  bullet-shaped, and a *second* structural anchor (`search.yaml`) found and distinct from the
  first — proving the extractor matches by structure, not by one hardcoded string.
- `test_model_routing_row_records_deprecation` — the guard: the row must say `deprecated`
  and `inert` (case-insensitive), must name the literal `src/construct/llm/config.yaml`, and
  must not match `_AUTHORITY_CLAIM` (`model-routing\.yaml`?\s+(?:stores|holds|controls|configures|drives|provides)\b`).

**Task 2 (GREEN) — `src/construct/services/init.py`** (commit `0f95f8d`)

Replaced the single Support Paths bullet in `_write_workspace_doc` (was line 175) with three
adjacent string literals concatenating into one markdown line:

```
- `.construct/model-routing.yaml` — **deprecated and inert**; nothing reads it. Retained only for workspace-contract stability. LLM configuration authority is `src/construct/llm/config.yaml`.
```

Nothing else in the file changed. In particular the `shutil.copy` of the model-routing
template at line 58 is untouched — the file remains a `REQUIRED_PATHS` entry per Phase 14 D-01.

The `_AUTHORITY_CLAIM` assertion sits downstream of the failing `deprecated` assert, so it
was never reached in the RED run. It was verified live and independently to confirm it is not
a dead assertion: against the old row it matched `'model-routing.yaml` stores'`. Both halves
of the guard therefore bite on the pre-fix text.
